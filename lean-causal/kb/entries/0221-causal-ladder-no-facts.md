---
id: 0221
title: causal_ladder's fact rules; a fact's witness module must not reach Causal.Ladder.Rules
kind: pitfall
created: 2026-11-22
---
`causal_ladder` makes rules of the ladder's checked implications and, since T-tac-ladder-integration, of its checked causality-sort `[[fact]]`s: a safe apply rule under the fact's standing (it closes `P t` for any causality term once the standing instances synthesise), plus a safe forward rule with the causality's rule pattern when an emitted edge reads the property. `curves_extend` is such a rule since T-tac-curves-fact-rule: `causal_ladder` closes `C.CurvesExtend` (and `C.dual.CurvesExtend`) on a `[T1Space M] [SecondCountableTopology M]` space with no hypothesis on `C`, apply only (no emitted edge reads `curves_extend`). Before, its witness's module `Causal.CurvesExtendSecondCountable` imported Rules through `Causal.MaximalZorn` → `Causal.ErsMughd`, so emit-lean skipped it as a cycle and `Causal.Ladder.Test` registered it locally. The cycle was broken by splitting the abstract Zorn theory (namespace `Causal.AbstractDev`, Mathlib imports only) out of `MaximalZorn.lean` into `Causal/AbstractDev.lean`, which `Causal.CurvesExtendSecondCountable` imports instead. The pitfall stands for any new fact: if its witness's module reaches `Causal.Ladder.Rules` (`tools/ladder.py`'s `import_chain(mod, lean_index()["imports"], RULES_MODULE)`), emit-lean writes a `-- skipped fact … cycle` line and only Test.lean has the rule. Split the witness's dependencies off the module that reaches Rules, as here, rather than discharging the property by hand. And keep the import closure of `Causal.CurvesExtendSecondCountable` (`Causal.AbstractDev`, `Causal.OmegaOneConstant`, `Causal.CBG.CausalConvex` and the 28 modules below them) clear of `Causal.Ladder.*`: Rules imports it, so a `causal_ladder` import anywhere below it is now an import cycle, and Lake refuses the build.
