A `[[property]]` of sort causality or pair may carry `dual` (T-tac-ladder-dual-key; schema docstring of `tools/ladder.py`). A two-sided node names its time-reversal lemma, `dual = "Causal.Causality.dual_isCausal"`: an iff `C.dual.P ↔ C.P` (a pair node reverses both causalities) or an implication `C.P → C.dual.P` (curves_extend has only `Causal.Causality.CurvesExtend.dual`). A one-sided node names what it introduces, `dual = { introduces = "causally_open", lemma = "Causal.Causality.causallyOpen_iff" }`: an iff `C.Q ↔ C.P ∧ C.dual.P`, a theorem taking both forms, or Q's own definition. `check` refuses a key on a geometry node, a lemma outside the ETT layer or in a module that is or imports `Causal.Ladder.Rules`/`Dual`, a statement of neither shape, and a counterexample the keys contradict across time reversal. `emit-lean` writes `Causal/Ladder/Dual.lean` and `DualTest.lean` from the keys, and never over a hand-written file (one whose first line is not the generated line): with keys present and the hand-written files in place, the dry run says `… is hand-written: kept`. To switch (T-tac-dual-generated), move DualTest's hand-written examples to a file of their own, remove the two hand-written files, then run emit-lean; kb/0264's last sentence (DualTest generated by `campaign/T-tac-ladder-dual/dual_closure.py`) is then stale. The 24 keys are `KEYS` in `campaign/T-tac-ladder-dual-key/keyed.py`; an introduction goes in the same edit as the key of the node it introduces.
